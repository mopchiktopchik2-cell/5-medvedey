# Приёмка: соответствие ожидаемым результатам

Документ сопоставляет пять ожидаемых результатов заказчика с тем, что реально сделано, где это лежит и как проверить за 10 минут.

| № | Ожидаемый результат | Статус | Где смотреть | Как проверить |
| --- | --- | --- | --- | --- |
| 1 | Сервис развёрнут и доступен по внутренней сети или закрытому URL | Готов к запуску в сети цеха; на внешнем VPS не развёрнут — нет доступа к серверу и домену | `scripts/start-lan.ps1`, `docker-compose.lan.yml`, README | Запустить `.\scripts\start-lan.ps1`, открыть `http://<IP>:8080` с другого компьютера |
| 2 | Заполненные справочники: ≥ 10 тканей, ≥ 5 фурнитуры, базовые типы изделий | Выполнено | `backend/app/seed.py`, `backend/tests/test_seed.py` | Войти технологом → «Справочники»; тест `pytest tests/test_seed.py` |
| 3 | Инструкция для менеджера | Выполнено: текстовый документ + сценарий показа | `docs/manager-guide.md`, `docs/demo-script.md` | Открыть документ, пройти шаги на стенде |
| 4 | Исходный код с комментариями и инструкцией по развёртыванию | Выполнено | репозиторий, `README.md`, `docs/` | Развернуть по README на чистой машине |
| 5 | Расчёт себестоимости и PDF за 5–10 минут | Выполнено | калькулятор, `POST /api/estimates`, `GET /api/estimates/{id}/pdf` | Пройти сценарий из `docs/demo-script.md` с секундомером |

## 1. Развёрнутый сервис

Что сделано:

- **Внутренняя сеть (пилот).** `scripts/start-lan.ps1` поднимает стек в Docker: фронтенд на порту **8080**, бэкенд внутри сети контейнеров. Скрипт сам создаёт `.env`, генерирует `SECRET_KEY`, включает демо-учётки и печатает адрес вида `http://192.168.1.42:8080`.
- **Закрытый URL.** Публичная ссылка на КП (`/share/<токен>`) живёт 30 дней, отзывается в один клик, не раскрывает внутренние данные. Это и есть «закрытый URL» для подрядчика.
- **Боевой контур.** `docker-compose.yml` + `docker-compose.postgres.yml`, миграции Alembic при старте, TLS-прокси — пошагово в README, раздел «Развёртывание на хостинге в РФ».

Честная оговорка: внешний VPS, домен и TLS в рамках этой работы не разворачивались — у разработчика нет доступа к серверу заказчика. Всё для этого готово, нужен сервер и домен.

Как проверить в сети цеха:

```powershell
cd 5-medvedey
.\scripts\start-lan.ps1
```

Скрипт выведет IP, демо-доступы и команду для брандмауэра. С другого компьютера открыть `http://<IP>:8080`, войти менеджером и построить расчёт. Остановка — `.\scripts\stop-lan.ps1`.

## 2. Справочники

Заполняются автоматически при первом запуске на пустой базе (`SEED_DEMO_DATA=true`, в LAN-режиме включено):

| Справочник | Количество | Примеры |
| --- | --- | --- |
| Ткани | 10 | кулирка, футер 2- и 3-нитка, интерлок, рибана, флис, канвас, оксфорд, полиэстер, джут |
| Фурнитура | 5 | пуговица, молния, нитки, люверс, шнур |
| Типы изделий | 4 | футболка, худи, шоппер, бейсболка |
| Сложность | 3 | базовая ×1.00, средняя ×1.25, сложная ×1.50 |
| Брендирование | 3 | термотрансфер, шелкография, вышивка |
| Подрядчики | 3 | ООО «Ромашка», ИП Смирнов, АО «СеверТрейд» |

Минимумы из ТЗ закреплены тестом `backend/tests/test_seed.py`, поэтому их нельзя случайно потерять при правках. Цены и нормо-часы — демонстрационные: технолог меняет их под фактические закупки, после чего расчёты сразу пересчитываются.

## 3. Инструкция менеджеру

`docs/manager-guide.md` — пошаговый текстовый документ: вход, выбор изделия и ткани, детали кроя, фурнитура, брендирование, сохранение, PDF, публичная ссылка, история и экспорт. Отдельно описаны смена пароля и срок жизни ссылки.

`docs/demo-script.md` — короткий сценарий показа на 5–6 минут с таймингами и готовыми формулировками. Его же удобно использовать как видео-гайд: записать экран, проговаривая шаги.

## 4. Исходный код и развёртывание

- Код разделён на слои: чистые формулы (`calculators.py`), сборка расчёта (`services.py`), API (`routers/`), модели и схемы. Модули снабжены docstring'ами, неочевидные места — комментариями.
- `README.md`: стек, формулы, структура, локальный запуск, Docker, LAN-пилот, хостинг в РФ, все переменные окружения, таблица API.
- `docs/technologist-guide.md` — для технолога: справочники, настройки, сотрудники.
- `docs/requirements-checklist.md` — матрица соответствия исходному ТЗ.
- Миграции Alembic с безопасным baseline, CI в GitHub Actions.

## 5. Расчёт и PDF за 5–10 минут

Замеренный сценарий (см. `docs/demo-script.md`): от входа до готового PDF — **3–5 минут** при известных параметрах, 5–8 минут, если параллельно уточнять цены у технолога. Что делает систему быстрой:

- смета пересчитывается на каждое изменение без перезагрузки страницы;
- справочники исключают ручной ввод цен и нормо-часов;
- черновик расчёта сохраняется в браузере;
- PDF собирается на сервере за один запрос, без Word и вёрстки;
- повтор расчёта открывает сохранённую смету со всеми параметрами.

## Приёмочный чек-лист

- [ ] `.\scripts\start-lan.ps1` поднимает сервис, сайт открывается с другого компьютера.
- [ ] Вход менеджером и технологом работает.
- [ ] В справочниках не меньше 10 тканей, 5 фурнитуры и 4 изделий.
- [ ] Расчёт футболки на 100 шт. занимает меньше 10 минут и сохраняется.
- [ ] PDF скачивается, в нём реквизиты, таблица и итог.
- [ ] Публичная ссылка открывается без входа, после отзыва — 404.
- [ ] Менеджер не видит чужие расчёты и не может править справочники.
- [ ] `pytest`, `npm test`, `npm run build`, `ruff check` проходят.

## Что нужно от заказчика для боевого запуска

1. Сервер (VPS) в РФ с Docker и домен.
2. Доступ к DNS для домена и TLS-сертификат (или Caddy с автоматическим TLS).
3. Реальные учётные данные SMTP, если КП должно уходить письмом.
4. Фактические цены тканей, фурнитуры и нормо-часы — их вносит технолог.
