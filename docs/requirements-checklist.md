# Соответствие техническому заданию

Проверка выполнена 14.11.2026. Матрица покрывает разделы 3–6 ТЗ: расчёт, модули, нефункциональные требования и стек.

Обозначения: **есть** — реализовано и проверено; **есть, с оговоркой** — реализовано, но требование зависит от окружения или допускает упрощение.

## 3.1. Базовые условия и константы

| Требование ТЗ | Статус | Где реализовано |
| --- | --- | --- |
| Стоимость нормо-часа швеи | есть | `Settings.sewing_normohour`, вкладка «Настройки» |
| Стоимость нормо-часа раскройщика | есть | `Settings.cutting_normohour`, вкладка «Настройки» |
| Ткани: название, ширина рулона, цена погонного метра | есть | `Fabric`, вкладка «Ткани» |
| Коэффициент межлекальных отходов 15–20% с ручным изменением | есть | По умолчанию 18%, поле в калькуляторе и настройка технолога; диапазон 15–20% подсвечивается |
| Фурнитура: фиксированная сумма на изделие или за штуку | есть | `Hardware.unit = per_item / piece`, количество на изделие в калькуляторе |
| Брендирование: фиксированная сумма за позицию | есть | `Branding.price`, количество позиций в калькуляторе |

## 3.2. Алгоритм расчёта пошива

| Требование ТЗ | Статус | Где реализовано |
| --- | --- | --- |
| Выбор типа изделия из списка | есть | Справочник «Изделия»: футболка, худи, шоппер, бейсболка |
| Тираж, сложность, подкладка, капюшон, карманы | есть | Форма калькулятора, коэффициенты 1.15 / 1.10 / 1.08 |
| Трудоёмкость = базовое время × сложность × тираж | есть | `calculators.py`, `services.py` |
| Стоимость пошива = трудоёмкость × нормо-час | есть | `SewingBreakdown` |

## 3.3. Алгоритм расчёта раскроя

| Требование ТЗ | Статус | Где реализовано |
| --- | --- | --- |
| Ткань из справочника, ширина рулона, цена | есть | Выбор ткани подставляет ширину и цену, поля редактируются |
| Размеры деталей в сантиметрах | есть | Строки деталей: название, длина, ширина, количество; готовые наборы по типу изделия |
| Количество деталей в комплекте | есть | `count_per_unit` |
| Площадь детали с припуском на шов | есть | Припуск по умолчанию 1.5 см, настраивается |
| Длина кроя с учётом ширины рулона и отходов | есть, с оговоркой | Эвристическая раскладка «полками» с поворотом деталей; для экспресс-расчёта достаточна, точную раскладку даёт САПР |
| Стоимость материала = метраж × цена | есть | `MaterialBreakdown` |
| Работа раскройщика = детали × тираж / норма выработки × нормо-час | есть | `CuttingBreakdown` |

## 5. Нефункциональные требования

| Требование ТЗ | Статус | Подтверждение |
| --- | --- | --- |
| Адаптивность: ПК, ноутбуки, планшеты | есть, с оговоркой | Вёрстка адаптивная; ручная проверка на 1440, 1024 и 768 px, скриншотов и автотестов в репозитории нет |
| Отклик интерфейса ≤ 1 с | есть | Локальный замер: предпросмотр расчёта в среднем 52 мс (10 замеров), справочники 11 мс. На рабочем сервере зависит от нагрузки и не измерялся |
| Полный цикл ввод + PDF ≤ 30 с | есть | Создание расчёта + PDF ≈ 193 мс на сервере; время ввода в браузере не измерялось |
| Черновик при обрыве связи | есть | Автосохранение формы в `localStorage`, подсказка в интерфейсе |
| Разграничение прав | есть | Менеджер — только свои расчёты, технолог — все, справочники и сотрудники; проверено тестами |
| Хеширование паролей | есть | argon2 |
| Защита от перебора пароля | есть, с оговоркой | Блокировка после 5 неудачных попыток входа на 15 минут; счётчик в памяти процесса, при нескольких воркерах действует на каждый отдельно |
| Срок жизни и отзыв публичной ссылки | есть | 30 дней по умолчанию (`SHARE_TOKEN_TTL_DAYS`), отзыв через `DELETE /api/estimates/{id}/share`; публичный ответ без email и ФИО сотрудника, нормо-часов и цены метра |
| Русский интерфейс, ДД.ММ.ГГГГ, рубли | есть | Все экраны, PDF и экспорт; форматтеры `format.ts` |

## Что добавлено при этой проверке

- Вкладка «Подрядчики» в справочниках: название, email для КП, телефон; создание и редактирование технологом.
- `PATCH /api/contractors/{id}` на фронтенде, ограничение записи ролью технолога.
- Управление сотрудниками: вкладка «Пользователи», смена роли, отключение, сброс пароля.
- Смена собственного пароля (`POST /api/auth/change-password`).
- Блокировка входа после серии неудачных попыток.
- Публичная ссылка со сроком жизни и отзывом; публичный ответ без внутренних данных.
- Alembic: baseline-миграция, `entrypoint.sh` в контейнере, проверка миграций в CI.
- Unit-тесты фронтенда на форматтеры (vitest).
- Инструкция технолога `docs/technologist-guide.md`.
- Матрица соответствия ТЗ и раздел о развёртывании в РФ.
- Отзыв всех сессий сотрудника при смене пароля, сбросе пароля технологом и смене роли (`users.token_version` + миграция).
- Импорт справочников из CSV: шаблоны, UTF-8/Windows-1251, `;`/`,`, частичный импорт с номерами ошибочных строк.
- Резервное копирование и восстановление (`scripts/backup.ps1`, `scripts/restore.ps1`) для PostgreSQL, SQLite в Docker и локального запуска.
- Боевой контур с Caddy: HTTPS, автоматический сертификат, CSP и заголовки безопасности; наружу только 80/443.
- Healthcheck-и backend/frontend в Docker и ротация логов контейнеров.
- Сквозной E2E на Playwright: вход, смета, история, PDF, импорт CSV; запускается локально и в CI на Docker-стенде.
- Раскадровка видео-гайда `docs/video-storyboard.md`.

Тестов сейчас: 75 бэкенд-тестов (pytest), 13 фронтенд-тестов (vitest) и 3 сквозных E2E-сценария (Playwright).

Пять ожидаемых результатов заказчика и приёмочный чек-лист — в [`acceptance.md`](acceptance.md). Сценарий показа на 5–6 минут — в [`demo-script.md`](demo-script.md), раскадровка видео — в [`video-storyboard.md`](video-storyboard.md).

## Оговорки

- Реальная отправка SMTP не проверялась без рабочих учётных данных. Без SMTP письмо сохраняется в `data/outbox/*.eml` — это штатный фолбэк.
- Раскладка кроя — эвристика, а не CAD-оптимизатор; в ТЗ требуется укрупнённый экспресс-расчёт.
- Схема БД создаётся миграциями Alembic; `create_all` при старте оставлен страховкой для чистой локальной базы.
- Подрядчик — это профиль для истории и отправки КП, отдельного входа для подрядчиков ТЗ не требует.
- Docker-образы собраны и запущены локально: проверены миграции в контейнере, вход, управление сотрудниками, публичная ссылка через nginx, HTTPS через Caddy с локальным сертификатом. Реальный сервер, домен и сертификат Let's Encrypt не проверялись.
- Реальная отправка писем через SMTP и деплой на VPS в рамках этой проверки не выполнялись.
